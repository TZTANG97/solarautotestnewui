SolarAutoTest Install Guide
===========================

Why install?
------------
Do NOT run the app from a shared network folder on multiple PCs.
Shared .venv / status.json / device locks will conflict.
Install a local copy on each PC.

Install steps (first time)
--------------------------
1. Unzip SolarAutoTest-Setup-YYYYMMDD.zip to a local folder.
2. Double-click install.bat
3. Choose install / data / runtime directories when prompted
   (Enter=default; type a path; or B=browse). Prefer D:/E: if available.
4. Wait for copy + uv sync + verify
5. Edit <InstallDir>\config_files\config.ini  [update] section
   (see Aliyun / LAN channel below)
6. Use desktop shortcut "SolarAutoTest"
6. IOT cloud (optional): edit config\iot_bootstrap.json → set iot_base
   to your IOT URL (e.g. http://iot-host:port/nss). First launch
   announces this PC (pythonid appears under 台架管理 → 从发现添加).
   After ops confirms add, this PC auto-claims the agent token.
   Do NOT copy solar_agent.json between PCs.

============================================================
Aliyun HTTP auto-update (EMKU OSS — recommended)
============================================================

Uses EMKU shared bucket (qgongye / Shanghai), separate folder:
  https://qgongye.oss-cn-shanghai.aliyuncs.com/solarautotest/updates/

A) Publish a new version (BUILD PC)
-----------------------------------
  packaging\build_release.bat -PublishEmkuOss

  Or only upload an already-built zip:
  packaging\Publish-To-EmkuOss.bat

  Credentials: read from E:\EMKU\ENV_环境切换.env (OSS_ACCESS_KEY_*),
  not committed into SolarAutoTest repo.

B) User first install (download link)
-------------------------------------
  Open latest.json, copy zip_url, or use:
  https://qgongye.oss-cn-shanghai.aliyuncs.com/solarautotest/updates/SolarAutoTest-Setup-YYYYMMDD.zip
  Unzip → run install.bat → desktop shortcut SolarAutoTest.

C) Bench PC auto-update (config.ini)
------------------------------------
[update]
enabled = 1
auto_install = 1
channel = https://qgongye.oss-cn-shanghai.aliyuncs.com/solarautotest/updates

Startup checks latest.json; if newer:
  - prefers incremental (only changed files via files-latest.json + blobs/)
  - falls back to full zip on first install / large change / incremental failure

Manual upgrade
--------------
Unzip new package and run install.bat again.

Folders
-------
- App:     chosen at install (default prefers D:\SolarAutoTest if D: exists,
           else %LOCALAPPDATA%\SolarAutoTest)
- Data:    <InstallDir>\data  or config_files\paths.ini data_root=
- Runtime: <InstallDir>\runtime or runtime_root.txt (venv / uv cache)
- Version: <InstallDir>\VERSION

Change disks later
------------------
1. Re-run install.bat and pick new folders, or
2. Edit <InstallDir>\config_files\paths.ini and runtime_root.txt, then restart.
Env overrides: SOLARAUTOTEST_DATA / SOLARAUTOTEST_RUNTIME / SOLARAUTOTEST_HOME

Avoid re-downloading Python deps after moving folders
----------------------------------------------------
Runtime (.venv + uv-cache) is separate from the app folder.
If you only moved the app and updates started a slow uv sync:

1. Find the OLD runtime that still has .venv\Scripts\python.exe
   (common: D:\SolarAutoTest\runtime  or  %LOCALAPPDATA%\SolarAutoTestRuntime)
2. Edit config_files\paths.ini:
     runtime_root = <that old path>
   and put the same path in runtime_root.txt (one line).
3. Restart. Installer will reuse it; no need to wait for PyPI.

New installs download wheels from China mirrors, not files.pythonhosted.org.
uv sync --frozen ignores the index URL and uses the URLs baked into uv.lock,
so the installer rewrites those URLs to a mirror with the same /packages/ path
(Aliyun, then Tencent, Huawei, Tsinghua) and still checks the lockfile hashes.
Python itself comes from the npmmirror python-build-standalone mirror.
The original uv.lock is restored after sync so upgrades keep the same file hash.

Notes
-----
1. Only one PC should control instruments on the same bench at a time.
2. Vendor drivers (e.g. NI-VISA) are NOT included.
3. Do not run the app directly from an update share / package URL.
4. First deploy after enabling auto-update: colleagues need one install.bat
   so they get the new Check-And-Update.ps1 + Start-SolarAutoTest.bat.
5. If HTTP download fails: check OSS public-read on solarautotest/updates/;
   for private objects set [update] token= only if you add auth later.
